# Bootstrap Installation Workflow

This document describes how to use collected artifacts to bootstrap a fresh OpenShift installation in a disconnected environment.

> **Note**: For interactive bootstrap workflows, use [OpenShift Airgap Architect](https://github.com/bstrauss84/openshift-airgap-architect/), which provides a UI-driven installation wizard that eliminates the need for manual field guides.

## Overview

The bootstrap workflow enables installing a new OpenShift cluster from scratch using only the artifacts collected by this pipeline. This is useful for:
- Initial cluster deployments in air-gapped environments
- Disaster recovery scenarios
- Creating new disconnected clusters

## Prerequisites

### Bastion Node Requirements

The bastion node is a helper machine that hosts the mirror registry and provides tools for installation:

**Operating System**: RHEL 8.6+ or RHEL 9.0+

**Resources**:
- CPU: 4 cores minimum (8 cores recommended)
- Memory: 16GB minimum (32GB recommended)
- Storage: 500GB+ available for registry storage

**Network**:
- Connectivity to future cluster nodes
- Resolvable hostname by cluster nodes
- Firewall allows registry traffic (port 8443)

## Required Tools in Archive

The collection archive should include these tools (configured via pipeline):

### Core Tools
- `openshift-install` - OpenShift installer binary
- `oc` - OpenShift CLI
- `kubectl` - Kubernetes CLI
- `oc-mirror` - Image mirroring tool
- `mirror-registry` - Tool to install Quay on bastion node
- `helm` - Helm CLI (if using Helm charts)

### Version Alignment
Ensure the OpenShift version in the archive matches your target cluster version. These are aligned during collection based on the ImageSetConfiguration.

## Installation Steps

### Using Airgap-Architect (Recommended)

For the best experience, use OpenShift Airgap Architect in airgapped mode:

1. **Import archive** using the Import Wizard

### Manual Installation (Current Process)

If not using airgap-architect, follow this workflow:

#### 1. Prepare Bastion Node

```bash
# Install required packages
sudo dnf install -y podman httpd-tools git jq

# Configure firewall
sudo firewall-cmd --permanent --add-port=8443/tcp
sudo firewall-cmd --reload
```

#### 2. Transfer and Import Archive

See `scripts/disconnected/bootstrap-import.sh` for automated import.

```bash
# Transfer archive via physical media
cp /mnt/usb/mirror-v2026.05.06.001-scheduled.tar.gz /tmp/

# Run import script
./scripts/disconnected/bootstrap-import.sh \
  /tmp/mirror-v2026.05.06.001-scheduled.tar.gz \
  quay.bastion.example.com:8443 \
  admin \
  <registry-password>
```

#### 3. Install Mirror Registry

If mirror-registry is not yet installed on bastion:

```bash
# Extract mirror-registry tool from archive
cd /tmp/mirror-v2026.05.06.001-scheduled/artifacts/binaries
tar -xzf mirror-registry.tar.gz

# Run installation
sudo ./mirror-registry install \
  --quayHostname $(hostname -f) \
  --quayRoot /opt/quay-install \
  --initPassword <strong-password>
```

#### 4. Create Install Configuration

Generate `install-config.yaml` with mirror registry settings:

```yaml
apiVersion: v1
baseDomain: example.com
metadata:
  name: ocp-cluster
networking:
  networkType: OVNKubernetes
  clusterNetwork:
  - cidr: 10.128.0.0/14
    hostPrefix: 23
  serviceNetwork:
  - 172.30.0.0/16
compute:
- name: worker
  replicas: 3
controlPlane:
  name: master
  replicas: 3
platform:
  vsphere:  # or baremetal, none, etc.
    # platform-specific configuration
pullSecret: '<REGISTRY_PULL_SECRET>'
sshKey: '<SSH_PUBLIC_KEY>'
additionalTrustBundle: |
  -----BEGIN CERTIFICATE-----
  <BASTION_REGISTRY_CA_CERT>
  -----END CERTIFICATE-----
imageContentSources:
- mirrors:
  - quay.bastion.example.com:8443/openshift/release
  source: quay.io/openshift-release-dev/ocp-v4.0-art-dev
- mirrors:
  - quay.bastion.example.com:8443/openshift/release-images
  source: quay.io/openshift-release-dev/ocp-release
```

**Tip**: The `imageContentSourcePolicy.yaml` file is generated by oc-mirror during import and can be found in the archive under `images/oc-mirror-workspace/results-*/`

#### 5. Generate Ignition Configs

```bash
# Extract openshift-install binary
cd /tmp/mirror-v2026.05.06.001-scheduled/artifacts/binaries
tar -xzf openshift-install-linux-*.tar.gz
sudo mv openshift-install /usr/local/bin/

# Create installation directory
mkdir -p /opt/openshift-install
cp install-config.yaml /opt/openshift-install/

# Generate ignition configs
openshift-install create ignition-configs --dir=/opt/openshift-install
```

#### 6. Boot Cluster Nodes

Method varies by platform:

**vSphere**: Create VMs and attach ignition configs via guestinfo
**Bare Metal**: Boot with ISO or PXE and provide ignition URL
**Agent-Based**: Use agent-based installer with ISO

See platform-specific documentation.

#### 7. Monitor Installation

```bash
# Wait for bootstrap to complete
openshift-install wait-for bootstrap-complete \
  --dir=/opt/openshift-install \
  --log-level=info

# After bootstrap completes, remove bootstrap node and continue
openshift-install wait-for install-complete \
  --dir=/opt/openshift-install \
  --log-level=info
```

#### 8. Access Cluster

```bash
# Export kubeconfig
export KUBECONFIG=/opt/openshift-install/auth/kubeconfig

# Verify cluster
oc get nodes
oc get clusterversion

# Access web console
oc get route -n openshift-console console -o jsonpath='{.spec.host}'
```

### Tools Inclusion

All required tools are automatically included in the artifact collection based on the ImageSetConfiguration and additionalImages specified.

## Troubleshooting

### Registry Connection Issues

```bash
# Test registry connectivity
curl -k -u admin:<password> https://quay.bastion.example.com:8443/health/instance

# Check registry status
sudo systemctl status quay-app

# View registry logs
sudo podman logs -f quay-app
```

### Installation Failures

```bash
# View installation logs
openshift-install wait-for install-complete --dir=/opt/openshift-install --log-level=debug

# Check bootstrap logs
ssh core@bootstrap-node
journalctl -u bootkube.service

# Check node status
oc get nodes -o wide
oc describe node <node-name>
```

### Image Pull Errors

Ensure imageContentSources in install-config.yaml matches the mirror registry output:

```bash
# Check imageContentSourcePolicy from oc-mirror
cat images/oc-mirror-workspace/results-*/imageContentSourcePolicy.yaml

# Verify images exist in registry
curl -k -u admin:<password> \
  https://quay.bastion.example.com:8443/api/v1/repository?namespace=openshift
```
